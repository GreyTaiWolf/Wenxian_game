# 通用任务目标系统

本文档定义《问仙》普通任务的配置契约、进度来源、前置条件、结算规则与旧存档兼容方式。主线目标负责告诉玩家“下一步做什么”，通用任务系统负责把任务榜中的接取、目标推进、材料扣除和奖励发放变成统一规则。

## 1. 代码职责

| 文件 | 职责 |
| --- | --- |
| `src/data/world.ts` | `TaskConfig`、`QuestObjective`、`QuestPrerequisite` 与任务内容配置 |
| `src/game/quests.ts` | 解锁、接取、进度派生、事件记录、提交、奖励与旧档归一化 |
| `src/game/combatEngine.ts` | 战斗胜利后记录击杀目标，不在 UI 中复制击杀规则 |
| `src/components/ExplorePanel.tsx` | 展示任务目标与进度；把到达、对话事件交给任务规则层 |
| `src/game/save.ts` | 读取旧档时补齐 `objectiveProgress`，迁移旧送信进度 |

## 2. 目标类型

| 类型 | 进度真值 | 当前用途 | 提交时处理 |
| --- | --- | --- | --- |
| `gather` | 当前背包物品数量 | 凝气草、妖兽骨、南疆材料 | 仅标记 `consumeOnComplete` 的目标扣除物品 |
| `kill` | 已接任务的 `objectiveProgress` | 山狼、妖藤、山魈、潮汐守卫 | 战斗胜利后按敌人模板计数 |
| `visit` | 已接任务的 `objectiveProgress` | 抵达落霞镇 | 地点移动完成后计数一次 |
| `talk` | 已接任务的 `objectiveProgress` | 拜访落霞镇驿亭执事 | 指定场景行动完成后计数一次 |
| `realm` | 当前境界实时派生 | 后续突破任务 | 不写重复状态 |
| `equip` | 当前穿戴实例实时派生 | 后续装备教学任务 | 不写重复状态 |

采集、境界与穿戴目标从真实游戏状态派生；击杀、到达与对话属于事件型进度，只在任务已经接取时写入。UI 不保存第二份任务进度。

## 3. 前置条件

当前支持：

- `quest`：前置任务至少已接取或已经完成；
- `cultivation`：完成指定次数聚气；高境界旧档视为已经满足新手聚气前置；
- `realm`：达到指定境界；
- `region`：处于指定州域；
- `sect`：要求已入宗或保持散修身份。

未满足前置的任务不显示完整任务内容，任务榜只给出下一条解锁提示。已经接取或完成的旧任务不会因为新增前置而重新锁定。

## 5. 结算护栏

1. 任务只能从 `available` 进入 `accepted`，不能重复接取。
2. 只有所有目标完成后才允许提交。
3. 材料检查与扣除使用同一份实时背包数据。
4. 状态先进入 `completed`，同一次提交不能重复领取奖励。
5. 奖励、贡献、声望和消耗集中在 `completeQuest()`，组件不再直接改资源。
6. 击杀只在胜利结算时记录；逃跑或战败不推进击杀目标。

## 6. 存档兼容

`QuestState` 保留旧字段 `status` 与 `progress`，新增 `objectiveProgress` 保存事件型目标计数。读取旧存档时：

- 缺少 `objectiveProgress` 自动补 `{}`；
- 非法、负数或非有限计数归一化；
- 旧版 `deliver_letter.progress > 0` 自动迁移为“已到达落霞镇 + 已与驿亭执事对话”；
- 已完成任务即使提交材料已经被扣除，界面仍显示全部目标完成。

## 7. 回归矩阵

| 场景 | 预期 |
| --- | --- |
| 新档未聚气打开任务榜 | 不提前显示采药详情，只提示先聚气 |
| 首次聚气后打开任务榜 | 采药任务变为可接取 |
| 未接任务先收集材料或击杀 | 事件型进度不记录；接取后按真实背包读取采集数量 |
| 接取黑风任务后击败狼群 | 山狼目标完成，妖兽骨到账后可提交 |
| 逃跑或战败 | 不增加击杀目标 |
| 接取送信后抵达落霞镇并对话 | 两项目标分别完成 |
| 提交采集任务 | 指定材料扣除一次，奖励只发一次 |
| 旧送信存档加载 | 旧 `progress=1` 转为两个事件目标完成 |
